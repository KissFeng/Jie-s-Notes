### 287. 比较 Vue Router 的 history 模式与 hash 模式的优缺点及适用场景。

> **参考答案：**
> 1. **history 模式（`createWebHistory()`）**
>    - **优点**：URL 不带 `#`，路径美观规范，更利于 SEO 搜索引擎抓取；
>    - **缺点**：依赖 HTML5 History API，上线后服务端必须配置路由回退（将未知路径重定向到 `index.html`），否则直接刷新页面会出现 404；
>    - **适用场景**：面向公众的 C 端网站、门户官网、电商站点等注重 URL 美观与 SEO 的项目。
> 2. **hash 模式（`createWebHashHistory()`）**
>    - **优点**：兼容性好，URL 中 `#` 后的内容不会发送给服务器，部署无需服务端额外回退配置，刷新不会 404；
>    - **缺点**：URL 带有 `#` 不够美观，且不利于 SEO；
>    - **适用场景**：后台管理系统、企业内部系统或无法修改服务器配置的项目。

### 288. 请简述Vue3中ref和reactive两个响应式API的核心区别

> **参考答案：**
> 1. **支持的数据类型**：`ref` 既可定义基本类型（number/string/boolean 等），也可定义对象/数组等引用类型；`reactive` 只能定义对象、数组等引用类型。
> 2. **访问与修改方式**：`ref` 在 `<script>` 中必须通过 `.value` 读写（模板中自动解包）；`reactive` 直接访问和修改对象属性，无需 `.value`。
> 3. **整体替换**：`ref` 可直接通过 `obj.value = newObj` 整体替换且保持响应式；`reactive` 直接整体重新赋值会丢失响应式（需用 `Object.assign` 或改用 `ref`）。
> 4. **底层实现**：`ref` 返回 `RefImpl` 对象（基本类型靠 getter/setter，引用类型内部仍借助 `reactive`）；`reactive` 直接基于 ES6 `Proxy` 实现深层响应式。

### 289. 请简单描述MVVM模式包含哪几个核心部分，他们的定义分别是什么

> **参考答案：**
> MVVM（Model-View-ViewModel）包含三个核心部分：
> 1. **Model（模型层）**：负责封装业务数据、状态以及与后端的数据交互逻辑（如接口请求、数据结构）。
> 2. **View（视图层）**：即用户看到的页面 UI 结构（HTML/CSS 模板），负责数据展示与触发用户交互事件。
> 3. **ViewModel（视图模型层）**：作为 View 与 Model 之间的核心桥梁，通过**数据绑定**将 Model 的数据自动同步渲染到 View，同时通过**事件监听**把 View 的用户操作反向写回 Model，实现视图与数据的双向同步解耦。

### 290. 写出 Vue3 组件生命周期的四个阶段及 7 个钩子，并选出三个钩子举例说明其应用场景。

> **参考答案：**
> - **四个阶段与 7 个核心钩子**：
>   1. **创建阶段**：`setup()`（组合式 API 入口，替代 Vue 2 的 `beforeCreate` / `created`）
>   2. **挂载阶段**：`onBeforeMount`（挂载前）、`onMounted`（挂载后）
>   3. **更新阶段**：`onBeforeUpdate`（更新前）、`onUpdated`（更新后）
>   4. **销毁（卸载）阶段**：`onBeforeUnmount`（卸载前）、`onUnmounted`（卸载后）
> - **三个钩子的典型应用场景**：
>   1. `onMounted`：组件首次渲染到 DOM 后执行，常用于**发起初始化接口请求**、**操作 DOM 或初始化第三方图表（如 ECharts）**；
>   2. `onUpdated`：响应式数据变化导致 DOM 重新渲染后执行，常用于**更新后重新计算 DOM 尺寸或调整图表大小**；
>   3. `onBeforeUnmount`：组件卸载前执行，常用于**清除定时器（`clearInterval`）、断开 WebSocket 连接、解绑全局事件监听**，防止内存泄漏。

### 291. 请对比Vue中计算属性和普通方法在实现数据加工逻辑时的核心差异，分别说明两者的执行特点与适用场景。

> **参考答案：**
> 1. **核心差异（缓存机制）**：
>    - **计算属性（`computed`）**：具有**缓存特性**，只有当其依赖的响应式数据发生变化时才会重新计算，否则多次访问直接返回缓存结果；
>    - **普通方法（`methods` / 函数）**：**没有缓存**，每次模板重新渲染或被调用时都会重新执行一次函数体。
> 2. **调用与执行特点**：
>    - 计算属性在模板中像普通属性一样直接引用（<code v-pre>{{ total }}</code>），不带括号，适合声明式派生状态；
>    - 普通方法调用需带括号（<code v-pre>{{ calcTotal() }}</code>），支持动态传参。
> 3. **适用场景**：
>    - **计算属性**：适合根据已有响应式数据派生新值（如购物车总价、列表过滤/排序、全名拼接），尤其是计算开销较大或被多次引用的场景；
>    - **普通方法**：适合事件处理回调、需要接收动态参数的格式化计算，或每次调用都必须重新执行（如获取当前时间戳）的场景。

### 292. 请简单描述MVVM模式包含哪几个核心部分，他们的定义分别是什么

> **参考答案：**
> MVVM（Model-View-ViewModel）包含三个核心部分：
> 1. **Model（模型层）**：负责封装应用的数据状态与业务逻辑（如从后端接口获取的数据）。
> 2. **View（视图层）**：用户直接交互的界面（HTML 模板与样式），负责将数据可视化展示给用户。
> 3. **ViewModel（视图模型层）**：连接 View 与 Model 的桥梁，负责将 Model 数据暴露给 View 自动渲染，并监听 View 的交互事件将变更同步回 Model，从而彻底解耦视图与数据。

### 293. 简述 ref 在 Vue 3 组合式 API 中的作用。

> **参考答案：**
> `ref` 在 Vue 3 组合式 API 中主要有两大核心作用：
